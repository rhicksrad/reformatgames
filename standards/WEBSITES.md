# Websites

The studio runs one studio site and one site per game. Policy IDs: WS1–WS4 in
[POLICIES.md](POLICIES.md); public-text rules (B1–B6) in
[RELEASES.md](RELEASES.md#public-text-and-legal-names).

## Conventions every site keeps

- **Static HTML (WS2).** No framework, no client build step. A multi-page
  site is generated by a Python script from a copy file and an image list, and
  the generated HTML is committed beside them. Edit the sources, rebuild,
  commit both.
- **Head tags (WS3)** on every page: `charset`, `viewport`, `<title>`,
  description, canonical URL, `robots`, `theme-color`, Open Graph (`og:type`,
  `og:site_name`, `og:title`, `og:description`, `og:image`, `og:url`), Twitter
  `summary_large_image`, and an icon (an inline SVG data URI is fine).
- **Structured data:** the studio site carries schema.org `Organization`
  with `sameAs` links to every game site and the itch account. A game site
  carries `VideoGame` (publisher and author `Reformat Games`, platforms,
  `Offer` with the itch URL and price) and a `VideoObject` per trailer
  (`uploadDate`, description, duration, thumbnail).
- **`sitemap.xml` and `robots.txt`** list every public page; update
  `lastmod` when a page changes. A custom `404.html`.
- **Fonts** from Google Fonts with `preconnect`, or a self-hosted OFL font with
  its licence.
- **Images** are current-build captures with descriptive alt text; captions
  sit outside the image (B5). The page's hero image loads with
  `fetchpriority="high"`.
- **Video:** H.264/yuv420p, fast-start, AAC kept, with a poster image. Large
  MP4s are kept out of the Pages artifact and served from the raw repository
  URL or R2. **[PS]**
- **Copy** is player-facing and signed Reformat Games; no personal names (B1).
  The footer reads `© <year> Reformat Games` or `© <year> Reformat Games LLC`
  where the legal entity is named ([CONFLICTS.md](CONFLICTS.md) D3).
- **Buy and download links** go to the itch page and say the state honestly
  (Early Access, free demo, free).
- Fiction games keep their disclaimer in the footer (B6).

## The studio site (reformatgames.com)

- The home page lists every game as a "file" with a one-line pitch, its site
  and its store link, and a news list with one line and a link per devlog.
- Per-game pages on this site (`galaxy-brain.html`, `shahanshah/`) are short
  landing pages that point to the game's own site.
- The look is the studio's retro terminal style: VT323 and IBM Plex Mono,
  phosphor colours in `styles.css` custom properties. New pages reuse
  `styles.css` rather than adding a second stylesheet.
- `standards/`, `templates/` and `tools/` in this repository are excluded
  from the published site by `_config.yml`.

## Deploying

- Pull before editing; never leave uncommitted edits in a site clone that a
  rebuild loop commits from.
- GitHub Pages sites deploy on merge to `main`. Cloudflare Worker sites deploy
  with `wrangler deploy` from the machine where wrangler is logged in; that is
  a production deploy (W3).
- The cloud proxy cannot always reach the live domains: check the result from
  a browser.
- After any deploy, open the live page and its media directly (WS4).

## A new game's site

1. Register the domain and point it at the chosen host.
2. Start from persianstrike.com's generator (`tools/build.py`,
   `tools/pages.py`, `tools/images.json`) and its `styles.css` structure, with
   the new game's palette and fonts.
3. Home page: hero capture, the pitch, the trailer, the store button,
   feature tiles, the fiction disclaimer if needed. An About page with the
   studio line and credits.
4. Add the game to reformatgames.com's games list, `Organization.sameAs`
   and the sitemap.
5. Add the site's deploy steps to the game's `HANDOFF.md`.
